## 五、额外增加的分析（超出必做要求）

| 内容 | 位置 | 作用 |
|---|---|---|
| 双 TMM 实现互检 + 解析校核 + 在线 TMM 交叉验证 | `src/validate_tmm.py`、`src/dreapex_crosscheck.py` | 证明物理内核正确（差异 < 1e−15） |
| λtarget 处反射率的物理上限（QW 解析 + 全局优化） | `src/optimize_bound.py` | 给设计任务一个性能天花板（0.6589） |
| 逐样本误差归因 | `src/attribution.py` | 解释失效机理：误差与光谱陡峭度正相关 |
| 高反射区局部加密对照实验 | `src/enrichment_experiment.py` | 证明数据分布比样本总量更关键 |
| 厚度公差敏感性 | `src/tolerance.py` | 工程落地评估 |
| 耗时基准与盈亏平衡规模 | `src/benchmark.py` | 诚实界定代理模型的价值边界 |
| 物理上限的网格穷举确认 | `src/bound_gridsearch.py` | 2.83×10⁶ 点独立确认上限（与解析差 8×10⁻⁶） |
| π 相位等价解家族 | `src/phase_family.py` | 解释最优解的简并性（4 个等价解） |
| 波长采样充分性检验 | `src/sensitivity.py` | 排除混叠解释（冗余 6 倍） |
| 局部采样密度归因 | `src/coverage.py` | 定位失败机理（r = 0.370，最稀疏组误差 +48%） |
| 目标波长加权损失对照 | `src/weighted_loss.py` | 该处 MAE 降 24%，但 Top1 仍不稳定 |
| 排名分辨率极限 | `src/ranking_limit.py` | 量化"尾部名次不可分辨" |
| 模型容量对照 | `src/capacity_experiment.py` | 判定误差瓶颈在数据还是容量（容量增至 3.7 倍，MSE 降 58%） |
| 容量×数据量网格 | `src/capacity_size_grid.py`、`src/fig_capacity.py` | 幂律指数随容量从 0.43 升至 1.38，容量与数据互补 |
| 精度→筛选转化 | `src/design_screen_capacity.py` | 大容量模型把 Top10 召回率从 60% 提到 80% |
| 随机基线对照 | `src/random_baseline.py` | 不用模型随机抽片作为 Q3 的对照基线 |
| 文献作者回归检查 | `src/check_consistency.py` | 强制比对权威源第一作者，防止文献著者错误 |
| 交付前一致性核查 | `src/check_consistency.py` | 19 项数值/文献/图件核查，全部一致方可交付 |
